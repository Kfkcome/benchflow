# BenchFlow v0.4 Test Plan

Date: 2026-05-17

## Purpose

Validate that BenchFlow v0.4 is release-ready after the Harbor removal and
runtime refactor. This plan is intentionally evidence-first: each area lists
what to run, what artifact proves success, and what failure means.

## Release Acceptance Criteria

v0.4 is ready only when all of these are true:

- Package metadata is `0.4.0`, lockfile is consistent, and changelog has a
  `0.4.0` section.
- Core install does not install Harbor or optional cloud/HuggingFace extras.
- Docker, Daytona, and Modal adapters are covered by unit/contract tests.
- ACP and acpx execution paths both produce BenchFlow result artifacts.
- Rubric/judge rewards and token/cost summaries are serialized into results.
- Docs in `benchflow/docs` are synchronized into the website MDX and the website
  build renders.
- Linear project `benchflow v0.4 refactor` has no non-canceled open issues.

## Tier 0: Static Release Gate

Run from `/Users/lixiangyi/benchflow/benchflow`.

```bash
rg -n '^version =|## 0\.4\.0' pyproject.toml CHANGELOG.md
uv lock --check
uv run ruff check .
uv run ty check src/
git diff --check
```

Pass criteria:

- `pyproject.toml` reports `version = "0.4.0"`.
- `CHANGELOG.md` contains `## 0.4.0 — 2026-05-17`.
- Ruff, ty, lock check, and whitespace check all pass.

Failure response:

- Version/lock mismatch: run `uv lock` after the version change and re-run this
  tier.
- Ruff/ty failure: fix before running live smokes; live results are noisy while
  the local tree is statically invalid.

## Tier 2: Harbor Removal And Core Install

```bash
rg -n 'from harbor|import harbor|harbor==|harbor>=|benchflow\[harbor\]|harbor\.' \
  src tests docs README.md pyproject.toml uv.lock

uv run --isolated --no-dev --exact python - <<'PY'
import importlib.metadata
import importlib.util
import benchflow
print(importlib.metadata.version('benchflow'))
print(benchflow.TaskConfig.__module__)
for name in ('harbor', 'daytona', 'modal', 'huggingface_hub'):
    print(f'{name}={importlib.util.find_spec(name)}')
PY
```

Pass criteria:

- `rg` exits with no matches.
- Isolated install prints `0.4.0`.
- `benchflow.TaskConfig.__module__` is `benchflow.task`.
- `harbor=None`, `daytona=None`, `modal=None`, and `huggingface_hub=None`.

Failure response:

- Any Harbor match in runtime or docs is release-blocking unless it is clearly
  historical release-note prose.
- Any optional dependency present in the isolated core install means a core
  dependency or extra leaked into the default package.

## Tier 4: Docs And Website

BenchFlow docs are the source of truth for website BenchFlow docs.

```bash
uv run python scripts/export_docs_to_website.py --check \
  --website-root ../www.benchflow.ai
```

If the check fails, regenerate website MDX:

```bash
uv run python scripts/export_docs_to_website.py --write \
  --website-root ../www.benchflow.ai
uv run python scripts/export_docs_to_website.py --check \
  --website-root ../www.benchflow.ai
```

Then render the website:

```bash
cd ../www.benchflow.ai
PATH="$HOME/.nvm/versions/node/v24.13.1/bin:$PATH" npm run build
```

Pass criteria:

- Exporter reports `BenchFlow website docs are in sync.`
- Next build completes and prerenders `/docs/benchflow/*` and `/raw/docs/*`.

Failure response:

- Export drift means update `benchflow/docs` first, then regenerate website MDX.
- Node version mismatch is not a docs failure; use Node `v24.13.1` or another
  version satisfying the website package engines.

## Tier 5: Live Docker Smokes

Run only when provider credentials are available.

ACP smoke:

```bash
OPENAI_API_KEY=... uv run bench eval create \
  --source-repo benchflow-ai/skillsbench \
  --source-path tasks/edit-pdf \
  --agent codex-acp \
  --model gpt-5.4-mini/low \
  --sandbox docker \
  --jobs-dir jobs/v0.4-smoke/codex-acp
```

acpx smoke:

```bash
OPENAI_API_KEY=... uv run bench eval create \
  --source-repo benchflow-ai/skillsbench \
  --source-path tasks/edit-pdf \
  --agent codex-acpx \
  --model gpt-5.4-mini/low \
  --sandbox docker \
  --jobs-dir jobs/v0.4-smoke/codex-acpx
```

Result inspection:

```bash
find jobs/v0.4-smoke -name result.json -print
jq '.agent, .model, .rewards, .trajectory_source, .token_usage, .total_cost_usd, .error' \
  "$(find jobs/v0.4-smoke -name result.json | head -n 1)"
```

Pass criteria:

- `result.json` exists for each run.
- `trajectory_source` is `acp` for `codex-acp` and `acpx` for `codex-acpx`.
- `error` is `null` or clearly task/verifier-scoped rather than harness/setup.
- Token usage fields exist even when a provider returns partial usage metadata.

Failure response:

- Auth errors are not release-blocking if unit/contract coverage is green, but
  they must be recorded separately from runtime failures.
- ACP/acpx protocol errors are release-blocking.

## Go / No-Go Summary

Go if:

- Tiers 0-4 and 8 pass.
- Tier 5 passes for at least one ACP path and one acpx path, or live-provider
  failures are clearly auth/provider availability rather than BenchFlow runtime.
- Tier 6 or Tier 7 passes when cloud credentials are available.

No-go if:

- Harbor appears in runtime deps/imports.
- Core install pulls optional adapters by default.
- ACP/acpx fails before agent task execution.
- Result artifacts omit rewards, trajectories, or usage/cost fields.
- Website docs drift from `benchflow/docs`.
- Linear has non-canceled open v0.4 refactor issues.
